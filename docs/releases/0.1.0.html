第一章

安装

需要带插件和原生自定义 agent 的 Codex 宿主，以及 jq。已安装的 marketplace 指向 GitHub 仓库 IpiggyI/codex-advisor，不是本地工作树。未推送的提交到不了已安装插件。

codex plugin marketplace add /absolute/path/to/codex-advisor
codex plugin add codex-advisor@codex-advisor
plugin_dir="$(codex plugin list --json | jq -r '.installed[] | select(.pluginId == "codex-advisor@codex-advisor") | .source.path')"
test -n "$plugin_dir" && test "$plugin_dir" != null && test -d "$plugin_dir" && test -f "$plugin_dir/scripts/install-agents.sh" && sh "$plugin_dir/scripts/install-agents.sh"

配套安装器把八个原生条目写到 $CODEX_HOME/agents；未设置时写到 ~/.codex/agents。保留无关 agent、已有 Sol Advisor 文件、以及主会话配置。目标已被改过、冲突、不是普通文件、或是符号链接时，写入前拒绝。内容完全相同的文件保持不动。

安装后开一个新任务。确认宿主暴露 codex-advisor:orchestration，以及安装器列出的原生条目。插件安装和原生 agent 发现是两件分开的事，都要查。

sh "$plugin_dir/scripts/install-agents.sh" --check

检出更新之后，重新安装插件，再跑配套安装器，然后开新任务。模板有更新时，已安装副本算冲突：先核对，再显式处理。安装器不会覆盖它们，也不会删除另一套安装。开发用临时 CODEX_HOME；空的临时 --target-dir 只检查、不改正在用的配置。

第二章

使用

Use $codex-advisor:orchestration to implement and verify this feature.

主会话在使用者给出的目标、范围、保留决策、验收条件和资源限制之内，决定怎么拆、怎么排、哪些自己做、哪些派出去。常规分配不必每次问准许。不要为了省事去改这些边界。

第三章

角色与档位

职责和档位分开。原生条目的名字区分模型和职责，不是额外档位。Luna 是多数实质探查的优先选择，不是先决步骤。本版没有 Explorer 的 xhigh 路线。

LIGHT · LUNA HIGH

Explorer

standard / senior 通常 Luna max；也可直接用 Sol 或 Astra 的 medium / high。

LUNA MAX

worker · light

钉死强度。局部实现选择归 worker，不再往下派实现。

SOL HIGH / XHIGH

worker · standard

第一次就可以用 xhigh，不必先失败。

ASTRA MEDIUM / HIGH

worker · senior、Advisor

同一次工作或咨询完整失败之后，才有资格用 xhigh。独立验收同属 Advisor。

派 worker 时给出结果、所属范围、必须保留的接口、约束和有意义的核对。未写明的局部实现选择归 worker。预期行为不清、需求冲突、或必须改保留接口，是合同缺口，先补合同再改依赖它的代码。

主会话保留拆分、调度和最终验收。共享文件不要拆成名义上互不相关的所有者。容量不够时不要靠嵌套 worker 绕过。独立且文件不冲突的派活可以并行；有依赖或所有权冲突的要串行。

第四章

Architect 模式

需要使用者明确授权。任意主模型都可以用。授权覆盖当前任务及其后续；无关任务要重新授权，除非使用者明确给了整段会话的范围。工单、规格、未接受的方案、或模型身份本身，都不会打开这个模式。把授权请求记下来。

打开之后，范围内的每一处实现编辑和修正都要派出去。主会话仍负责设计、合同、调度和验收，可以写设计和任务文件。

Use $codex-advisor:orchestration in Architect mode for this task.
第五章

判断与验收

ADVISOR

必须问 Advisor

  • 现行计划盖不住的关键决策
  • 新证据推翻了计划里的关键前提
  • 初步诊断之后，失败原因仍不清楚

前提仍成立时可以复用已有建议。建议不授予权限、不构成否决、不新增约束、也不接管使用者目标。

INDEPENDENT REVIEWER

独立验收

高风险交付，或使用者明确要求独立审查时，主会话检查之后必须再开一个全新的 Astra Independent reviewer。

风险看失败后果、可否挽回、以及正确性是否难确认。先前的咨询或 worker 自评都不能代替独立终验。

普通的直接做、派出去做、或两者混合的多步工作，主会话检查实际改动并重跑关键核对之后即可结束。步数、文件数、主模型身份、或只是 Astra 去做实现，都不单独触发交付咨询或独立验收。

审查强度一开始用 medium 或 high，不跟主会话强度挂钩。主会话即使是 max，审查也可以是 medium。有实质发现时先改、主会话再核、再开新线程审查改后的交付。

必需的执行跑不了、设置不受支持、证据缺失或互相打架、或实质发现未解决时，受影响的验收明确标为未完成。只读请求、观察到的只读行为、宿主强制隔离，三者分开报告。

第六章

失败与交接

一次完整的 worker 尝试包含实现、普通排错和核对，然后验收失败，或明确做不完目标。中途测试失败和单次工具报错，不算完整失败。

先分清环境问题、缺事实、合同缺口、推理失败、以及执行者是否合适。先修环境和补合同。之后可以原分配返工、换强度、换更合适的 worker，或由主会话接手。没有固定升级梯子。普通工作允许主会话接手；Architect 模式里修正仍要派出去。

XHIGH

xhigh 资格

  • Astra worker：同一次工作的 worker 完整失败之后
  • Sol worker：第一次就可以用，不必先失败
  • Advisor：咨询没有答出所问，或结论被证据推翻。worker 失败不能解锁
THREAD

新线程

  • 换强度、换模型、换职责：开新线程
  • 同一模型同一强度的 worker 返工：可沿用
  • 独立验收：永远开新线程

换写者之前，停掉仍在冲突写入的前任，看实际改动，保留有用的部分。交接包含：目标与已绑定决策、当前实际状态、尝试与诊断、剩下的工作。验收条件不因此降低。

第七章

八个原生条目

Luna 钉死 gpt-5.6-luna，Sol 钉死 gpt-5.6-sol，Astra 钉死 gpt-6-astra。只有 Luna worker 把强度钉成 max；其余由调用方每次显式传入。不要改角色文件或主会话配置来调强度。

职责 原生条目 强度
light workercodex_advisor_luna_implementer · lunamax
standard workercodex_advisor_sol_implementer · solhigh，xhigh（第一次即可）
senior workercodex_advisor_astra_implementer · astramedium，high；符合条件后 xhigh
优先探查codex_advisor_luna_explorer · explorerlight 用 high，其余 max
直接探查codex_advisor_sol_explorer · sol-explorermedium，high
直接探查codex_advisor_astra_explorer · astra-explorermedium，high
决策咨询codex_advisor_astra_advisor · advisormedium，high；符合条件后 xhigh
独立验收codex_advisor_astra_reviewer · reviewermedium，high；符合条件后 xhigh

已安装的 Explorer 和判断条目，不加载本技能也可以调用。只安装它们，并不会变成全局默认探查路线。每次调用都要带上强度。用 fork_turns: none 发送完整合同。角色自称的设置不能当实际设置。

第八章

核对

运行时英文文档在 plugins/codex-advisor/**/*.md。每个文件在 docs/zh/ 下有一份中文镜像，一对一存在，不核内容。镜像只在仓库里，不随插件下发。当前编排政策以 ADR-0003 为准。

sh plugins/codex-advisor/scripts/verify.sh --installation
sh plugins/codex-advisor/scripts/verify.sh --runtime
sh plugins/codex-advisor/scripts/verify.sh
git diff --check
python3 tests/test_zh_mirror.py

这些检查证明安装、分配和证据一致性。小规模原生冒烟不证明普遍质量、稳定或省钱。

第九章

本版边界

  • 只支持 Codex，没有其他宿主适配。
  • 没有调度器、提供方桥、预算服务或配置档案模式。
  • 安装器不改主会话配置，不覆盖已改过的角色文件，不自动迁移或删除另一套安装。
  • 只读请求、观察到的只读行为、宿主强制隔离，三者分开记录。
  • 路线核对和验收记录是一次性证据，不是发布资产。
第十章

相对上一版

这是第一份按版本冻结的说明书。codex-advisor 此前没有带版本号的说明书，历史提交不补写。下面是相对上游 Sol Advisor 的差。

  • 改插件改名为 codex-advisor，只面向 Codex。
  • 删去掉 solo / delegate / audit / full 任务路由，以及 SELECTIVE ROUTE 声明协议，不保留兼容层。
  • 改任意主模型都可以自己做、派活、或混合；Architect 改为使用者明确授权，不再绑定 Astra 主会话。
  • 增角色按 light / standard / senior 分档，配齐八个钉死模型的原生条目，含 Luna / Sol / Astra Explorer，以及分开的 Advisor 与 Independent reviewer。
  • 增worker 合同固定为结果、范围、保留接口、约束、核对五段；局部实现选择归 worker。
  • 改独立验收只在高风险或使用者明确要求时触发。审查强度不跟主会话强度挂钩。
  • 改Astra worker 的 xhigh 要先完整失败；Sol worker 的 xhigh 第一次就可以用；Advisor 的 xhigh 只在咨询完整失败后解锁。
  • 增换强度、换模型、换职责都开新线程；独立验收永远开新线程。
  • 增仓库增加运行时中文镜像（docs/zh/）和按版本冻结的说明书页面。镜像和说明书都不随插件下发。
