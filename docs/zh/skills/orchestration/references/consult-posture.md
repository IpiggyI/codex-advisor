# 过程咨询姿态

把调用者的精确模型标识与 routing profile 分配的 Advisor dial 的模型标识进行比较，以选择姿态。两个标识相同则使用 reduced 姿态；不同则使用 full 姿态。未知的调用者模型也采用同一标识规则：例如，当分配到的 Advisor 使用不同的精确模型标识时，`gpt-5.6-terra` primary 使用 full 姿态。不要根据模型家族推断姿态。

原样复制或注入所选姿态块。两种姿态都应用 adoption 块。

<!-- consult-posture:full:start -->
在开始实质性工作之前调用过程咨询。定向查找不算实质性工作：寻找文件、阅读来源和查看现状属于定向查找；写作、编辑和给出答案属于实质性工作。

遇到阻滞时调用过程咨询：错误反复出现、方法无法收敛，或结果相互矛盾。改变方法之前也要调用。

宣布完成之前调用过程咨询。调用前，先写入或保存交付物，使其在咨询中断时仍然存在。

对于多步骤任务，至少在确定方法之前调用一次，并在宣布完成之前调用一次。若短任务的下一步直接由刚读到的工具输出决定，则无需咨询。

当先前证据指向一个方向，而咨询建议指向另一个方向时，再做一次 reconcile call，不要静默切换。

每次咨询得到结果后，继续工作之前，在下一条用户可见回复中重述其关键指导。引用或转述 plan、correction 或 stop signal；不要只把它留在折叠的工具输出中。

仅在多步骤任务中调用过程咨询：在确定方法之前和宣布完成之前各调用一次。在完成前的调用之前，先写入或保存交付物，使其在咨询中断时仍然存在。

每次咨询得到结果后，继续工作之前，在下一条用户可见回复中重述其关键指导。引用或转述 plan、correction 或 stop signal；不要只把它留在折叠的工具输出中。
<!-- consult-posture:reduced:end -->

<!-- consult-posture:adoption:start -->
结果包含 `consultationDisabled: true` 时，停止本线程的所有过程咨询，包括完成前咨询和协调咨询。报告咨询不可用，继续已授权的工作与必要检查。同一线程累计第 4 次调用失败后停用咨询；重新打开该线程不会清零。用户审批和独立验收要求仍然有效。

默认采纳咨询建议。

遵循某一步骤实际失败，或第一手来源证据反驳某项具体主张时，可以偏离建议，但要说明理由。自测通过不能证明建议错误。

建议与用户约束、授权、保留接口或仓库规则冲突时，直接拒绝并说明理由。

因推理缺陷而拒绝建议时，比较精确模型标识。Advisor 的模型与调用者不同时，先做一次 reconcile call：“我发现 X，你建议 Y；哪个约束决定取舍？”两个模型标识相同时，可以直接拒绝并说明理由。

建议不授予授权、否决权或新要求。
